# 📘 📘 База ООП

## 📝 День 1: Day1

День 1 — Базовая модель банковских счетов (усложнённый вариант)

### 🎯 Цель дня
Создать расширенную и абстрактную модель банковского счёта, способную служить базой для более сложных типов счетов.

### 📋 Требования

#### 1. Абстрактный класс AbstractAccount
Создать абстрактный класс, содержащий:
- 🔑 уникальный идентификатор счёта
- 👤 данные владельца
- 💰 защищённый баланс
- 📊 статус счёта: активный, замороженный, закрытый
- 🔧 абстрактные методы:
  deposit(amount)
  withdraw(amount)
  get_account_info()

#### 2. Класс BankAccount
Реализовать конкретный тип счёта с расширенными возможностями:
- ✅ валидация входящих данных
- 🔒 логические статусы и запрет операций при неверных статусах
- 🆔 автоматическая генерация короткого UUID при отсутствии номера счёта
- 💱 атрибут currency: RUB, USD, EUR, KZT, CNY

#### 3. Исключения
Создать собственные классы ошибок:
- ❄️ AccountFrozenError
- 🚫 AccountClosedError
- ⚠️ InvalidOperationError
- 💸 InsufficientFundsError

#### 4. Базовые операции
Добавить проверки:
- ✅ корректность суммы
- 🔄 проверка статуса счета
- 🛡️ защита от отрицательных значений

#### 5. Строковое представление
Метод __str__ должен показывать:
- 🏦 тип счета
- 👤 клиента
- 🔢 последние 4 цифры номера
- 📊 статус
- 💰 баланс и валюту

#### 6. Тестирование
Создать демонстрацию:
- ➕ создание активного и замороженного счёта
- 🚫 попытка операций над замороженным счётом
- ✅ валидное пополнение и снятие

## ✅ Реализация Day1

Все основные требования первого дня реализованы в файле `main.py`.

### Реализованные возможности

- Абстрактный класс `AbstractAccount` с использованием `ABC` и `@abstractmethod`.
- Наследование и реализация методов в классе `BankAccount`.
- Создание банковских счетов с указанием владельца, баланса, статуса и валюты.
- Автоматическая генерация коротких UUID для новых счетов.
- Проверка уникальности номеров счетов в пределах одного запуска программы.
- Поддержка пяти валют: RUB, USD, EUR, KZT, CNY.
- Поддержка трёх статусов: `active`, `frozen`, `closed`.
- Пополнение и снятие средств с проверкой корректности операций.
- Запрет операций с замороженными и закрытыми счетами.
- Защита от отрицательного баланса, некорректных типов данных, `NaN` и бесконечности.
- Четыре собственных класса исключений.
- Получение информации о счёте через `get_account_info()`.
- Строковое представление счёта через `__str__()`.

### Использованные инструменты Python

- `abc` — создание абстрактных классов и методов.
- `uuid` — генерация уникальных идентификаторов.
- `math` — проверка числовых значений.
- `set` — хранение использованных номеров счетов.
- `try` / `except` — обработка исключений.

Все используемые модули входят в стандартную библиотеку Python. Установка внешних библиотек для Day1 не требуется.

## Day 2 — Продвинутые типы банковских счетов

Во второй день реализованы три дочерних класса банковских счетов на основе BankAccount.

### SavingsAccount
- Минимальный остаток на счёте.
- Месячная процентная ставка.
- Начисление процентов через apply_monthly_interest().
- Запрет снятия средств ниже минимального остатка.
- Проверка корректности параметров.

### PremiumAccount
- Повышенный лимит снятия.
- Возможность овердрафта.
- Фиксированная комиссия за снятие.
- Проверка ограничений и статуса счёта.

### InvestmentAccount
- Инвестиционный портфель в виде словаря.
- Поддержка stocks, bonds и etf.
- Распределение средств методом invest().
- Расчёт ожидаемого годового прироста через project_yearly_growth().
- Проверка допустимости активов и достаточности средств.
- Раздельный учёт свободных и инвестированных средств.

### Принципы ООП
- Наследование от BankAccount.
- Переопределение withdraw(), get_account_info() и __str__().
- Полиморфизм при работе с разными типами счетов.
- Обработка ошибок с помощью собственных исключений.

### Тестирование
Проверены успешные операции, ограничения по балансу,
овердрафт, комиссии, начисление процентов, инвестиции,
прогноз доходности, замороженные счета и некорректные данные.
